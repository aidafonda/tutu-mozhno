# Что потребуется для запуска в Туту

## 1. Данные и владельцы

- договориться о единой схеме доступности вокзалов, аэропортов, остановок, транспорта и пересадок;
- назначить владельца каждого факта, дату проверки, TTL и процесс обновления;
- подключить статусы лифтов, платформ, заявок сопровождения и последней мили;
- завести обратную связь о расхождении с реальностью и очередь ручной модерации;
- хранить требования пользователя, а не медицинский диагноз.

## 2. Сервисный контур

- вынести правила оценки и реестр в отдельный версионируемый сервис;
- использовать внутренние API и идентификаторы Туту вместо публичного MCP как единственную производственную зависимость;
- добавить кэш, circuit breaker, ограничение запросов, retry с jitter и явные тайм-ауты;
- публиковать метрики latency, error rate, долю неизвестных условий, возраст фактов и `false-safe`-инциденты;
- добавить распределённую трассировку и корреляцию по `X-Request-Id`;
- развернуть минимум две реплики, readiness/liveness probes и управляемые секреты.

## 3. Качество и безопасность

- контрактные тесты на схемы транспортных API и реестра;
- e2e-тесты поиска и перехода в оформление для поездов, авиа и автобусов;
- нагрузочные и отказоустойчивые тесты, SLO и алерты;
- threat modeling, SAST, dependency/container scan, аудит логов на персональные данные;
- доступность интерфейса по WCAG: клавиатура, screen reader, контраст, масштаб 200% и тесты с реальными пользователями.

## 4. Продуктовый rollout

1. Shadow-режим на нескольких железнодорожных направлениях: расчёт без показа пользователю.
2. Закрытый пилот с профильными организациями и службой поддержки.
3. Эксперимент в выдаче: понимание статусов, переход в оформление, время выбора, обращения в поддержку.
4. Расширение реестра и видов транспорта только после выполнения порога свежести и полноты данных.
5. Полноценный запуск с ответственным SLA и процессом расследования ошибочных рекомендаций.

## Решение по архитектуре

UI прототипа можно перенести в React/Next.js, продуктовые правила — в Go-сервис, развернуть в OpenShift/Kubernetes и подключить внутренние наблюдаемость и хранилища Туту. Это целевая гипотеза интеграции, а не утверждение о согласованной архитектуре компании.
